# Money Transfer System

## v1 — Пользователи и базовые операции

* Создал структуру `User` с полями `ID`, `Name` и `Balance`.
* Реализовал методы `Deposit` и `Withdraw`.
* Добавил проверку недостаточного баланса при снятии средств.
* Создал нескольких пользователей и проверил работу методов.

**Почему:** чтобы реализовать базовую работу с балансом пользователя.

## v2 — Платёжная система и транзакции

* Создал структуры `PaymentSystem` и `Transaction`.
* Реализовал добавление пользователей через `AddUser`.
* Реализовал добавление транзакций через `AddTransaction`.
* Добавил обработку переводов через `ProcessingTransactions`.
* Добавил проверки существования отправителя и получателя.
* Добавил проверку достаточности средств.
* Реализовал последовательную обработку нескольких транзакций через `for`.

**Почему:** чтобы хранить пользователей и обрабатывать переводы между ними через единую платёжную систему.

## v3 — Конкурентная обработка транзакций

* Добавил передачу транзакций через буферизованный канал.
* Реализовал `Worker`, который получает транзакции из канала.
* Запустил несколько воркеров в отдельных горутинах.
* Использовал `sync.WaitGroup` для ожидания завершения всех воркеров.
* Проверил программу через `go run -race .` и обнаружил `data race` при одновременном изменении `Balance`.

**Почему:** чтобы транзакции могли обрабатываться конкурентно несколькими воркерами.

## v4 — Защита от Data Race

* Добавил `sync.Mutex` для защиты баланса пользователя.
* Защитил операции `Deposit` и `Withdraw` от одновременного изменения `Balance` несколькими горутинами.
* Повторно проверил программу через `go run -race .`.
* После добавления `Mutex` race detector больше не обнаруживает `data race`.

**Почему:** несколько воркеров могут одновременно работать с одним пользователем, поэтому доступ к `Balance` необходимо синхронизировать.
